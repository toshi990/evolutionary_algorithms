# Отчёт по лабораторной работе №2

## Генетический алгоритм для дискретной задачи с ограничениями

Группа Б24-517. Вариант 14.
N = 20, Q = 1, Y = 26.
Номер варианта: V = 1 + ((17 · 20 + 7 · 1 + 26) mod 20) = 14.

## Цель работы

Разработать дискретное представление решения и генетические операторы для
расстановки наблюдательных пунктов. Сравнить штраф и восстановление допустимости,
а также два способа мутации.

## Постановка задачи и исходные данные

Дан неориентированный граф G = (U, E) из 36 вершин и 63 рёбер.
Можно установить не более 4 пунктов. Пункт покрывает свою вершину и её
непосредственных соседей, то есть вершины на расстоянии одного ребра.
Нужно покрыть как можно больше вершин.

Пусть N[v] — множество, состоящее из вершины v и её соседей. Для множества пунктов
S ⊆ U целевая функция и ограничение имеют вид:

C(S) = |⋃_{v ∈ S} N[v]| → max,  |S| ≤ k = 4.

Входные данные сохранены в [graph.json](data/graph.json).
Граф сгенерирован с seed = 20261420: сначала построен цикл из
36 вершин, затем между ещё не соединёнными парами добавлены рёбра с
вероятностью 0.045. Пары перебирались в порядке
возрастания номеров. Цикл обеспечивает связность. Координаты на окружности нужны
для рисунка и в расчёте покрытия не используются.

## Кодирование и ограничения

Хромосома — бинарный вектор длины 36. Единица в позиции i означает пункт
в вершине i. При декодировании получается множество пунктов S, после чего
объединяются их окрестности. Такое кодирование непосредственно описывает выбор
вершин. В файле графа индексы начинаются с нуля, в отчёте и рисунках — с единицы.

Допустимы хромосомы, у которых сумма единиц не превышает 4.
Добавление пункта не уменьшает покрытие, поэтому хотя бы одно оптимальное
решение содержит ровно k пунктов. Это позволяет при ремонте дополнять решение
до k единиц, а при точном переборе и случайном поиске рассматривать k-подмножества.

Примеры решений на исходном графе:

| Пункты | Число пунктов | Покрытие | Допустимо |
| --- | ---: | ---: | --- |
| 1 | 1 | 3 | Да |
| 1, 2, 3, 4 | 4 | 12 | Да |
| 1, 2, 3, 4, 5 | 5 | 13 | Нет |
| Все вершины | 36 | 36 | Нет |

## Генетический алгоритм

Начальная популяция состоит из случайных наборов ровно по k пунктов.
Для выбора родителя проводится турнир: из популяции с возвращением выбираются
кандидаты, побеждает особь с наибольшим значением функции приспособленности.
Лучшие особи переносятся в следующее поколение без повторного вычисления оценки.

При равномерном кроссовере каждый бит потомка с вероятностью 1/2 берётся у
одного из родителей. Это позволяет сочетать выбранные вершины родителей,
но число пунктов у потомка может измениться.

Сравнивались две мутации. Инверсия меняет один случайный бит. Обмен убирает
один выбранный пункт и добавляет один в свободной вершине. Обмен соответствует
переносу пункта на графе и сохраняет число единиц.

Ограничения обрабатывались двумя способами:

- **Штраф:** F(x) = C(x) − λ · max(0, Σxᵢ − k), λ = 37.
  При использованном λ > 36 любая недопустимая особь имеет отрицательную
  оценку, допустимая — неотрицательную.
- **Ремонт:** случайно удаляются лишние единицы или добавляются недостающие
  до k. Ремонт выполняется после кроссовера и мутации, перед оценкой потомка.

Лучшее допустимое решение сохраняется отдельно. Алгоритм останавливается по
бюджету вычислений покрытия; последнее поколение может быть неполным.

Для каждого метода проведено по 20 запусков. Сначала сравнивались
штраф и ремонт при одинаковой инверсии бита. Затем при ремонте сравнивались
инверсия и обмен. В каждой паре менялся один фактор.
Случайный допустимый поиск независимо выбирал наборы по k вершин при том же бюджете.

В бюджет включены оценки начальной популяции и всех новых кандидатов, в том
числе повторившихся. Ремонт не вычисляет покрытие. Время измерялось только для
поиска, без построения графиков и точного перебора. Настройки сохранены
в [config.json](config.json).

## Анализ результатов

При штрафе среднее покрытие составило 22.3, при ремонте —
23. Оптимум достигнут в 10 и
20 из 20 запусков соответственно. В штрафной схеме допустимыми оказались
67.16% оценённых кандидатов. Ремонт обеспечил
допустимость всех кандидатов, поэтому весь бюджет расходовался на допустимые
решения. Кроме того, он восстанавливал ровно k пунктов, что полезно для
монотонной функции покрытия.

Обе мутации с ремонтом дали одинаковое итоговое качество: среднее покрытие 23, оптимум достигнут в 20 из 20 запусков каждой конфигурации. По этим результатам нельзя выбрать лучшую мутацию. Обмен сразу сохраняет число пунктов; после инверсии это число восстанавливается ремонтом.

Случайный допустимый поиск получил среднее покрытие 22.15 и достиг
оптимума в 7 из 20 запусков. Для ГА с ремонтом
и обменом среднее равно 23, число достижений оптимума —
20 из 20. Это сравнение относится к одному графу
и не позволяет перенести вывод на любые графы.

## Вывод

Реализованы бинарное кодирование, равномерный кроссовер, инверсия и обмен,
штраф и ремонт. Найденное покрытие 23 совпало с точным оптимумом 23. Результат оптимален для заданного графа и ограничения на число пунктов, хотя часть вершин остаётся без покрытия.
При одинаковом бюджете сравнены два способа обработки ограничений
и две мутации.
