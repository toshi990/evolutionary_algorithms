# Отчёт по лабораторной работе №3

## Многокритериальный выбор оборудования для экспедиции

Группа Б24-517. Вариант 14, трек A.
N = 20, Q = 1, Y = 26.
V = 1 + ((17 · 20 + 7 · 1 + 26) mod 20) = 14.

## Цель работы

Реализовать многокритериальный генетический алгоритм и исследовать компромиссы
между полезностью, массой и надёжностью оборудования. Сравнить NSGA-II
с генетическим алгоритмом на основе взвешенной суммы критериев.

## Постановка задачи и кодирование

Даны 30 предметов, разделённых на 10 обязательных
категорий: палатка, спальный мешок, горелка, фильтр воды, навигация, связь,
аптечка, освещение, питание электроники и защитная одежда.
Из каждой категории выбирается ровно один из трёх вариантов.
Комплект кодируется вектором x = (x₁, …, x₁₀), xᵢ ∈ {0, 1, 2}.
При декодировании каждый номер заменяется соответствующим предметом.
Таким образом, допустимость обеспечивается самим представлением.

Критерии:

U(x) = Σuᵢ(xᵢ) → max — суммарная полезность, баллы;

M(x) = Σmᵢ(xᵢ) → min — суммарная масса, граммы;

R(x) = ∏pᵢ(xᵢ) → max — надёжность комплекта.

Надёжность трактуется как вероятность исправности всех предметов
при независимых отказах. Резервирование и ремонт не учитываются.
Для сравнения решений все критерии приведены к минимизации: (−U, M, −R).
Вероятности хранятся в тысячных долях; при сравнении используются целые
произведения с общим знаменателем 1000¹⁰. Округление процентов на результат
доминирования не влияет.

Критерии конфликтуют: облегчённые варианты уменьшают массу, функциональные
увеличивают полезность, а надёжные повышают вероятность исправности за счёт
большей массы. Поэтому ищется набор компромиссов Парето.

## Исходные данные

Использованы синтетические данные с seed = 20261403.
Все значения сохранены в [equipment.json](data/equipment.json).
Для каждой категории заданы базовые масса и полезность в функции `generate_data`
модуля [problem.py](algorithms/problem.py). Альтернативы генерируются
в порядке «облегчённая, функциональная, надёжная» по следующей схеме:

| Вариант | Доля базовой полезности | Доля базовой массы | Вероятность исправности |
| --- | --- | --- | --- |
| Облегчённый | 0.72–0.84 | 0.58–0.72 | 0.900–0.945 |
| Функциональный | 1.10–1.24 | 0.92–1.08 | 0.945–0.973 |
| Надёжный | 0.88–1.04 | 1.25–1.47 | 0.983–0.997 |

Множители выбираются равномерно, полезность и масса округляются до целого,
надёжность выбирается целым числом в тысячных долях. Эти оценки описывают
учебный набор и не являются характеристиками реального снаряжения.

## NSGA-II и операторы

Решение a доминирует b, если оно не хуже по всем критериям и строго лучше
хотя бы по одному. Недоминируемая сортировка разбивает популяцию на фронты:
в первый входят недоминируемые решения, затем они исключаются и строится
следующий фронт.

Разнообразие поддерживается расстоянием до скопления (crowding distance).
Внутри фронта складываются расстояния между соседями по каждой оси,
делённые на диапазон этого критерия. Крайние точки получают бесконечное
расстояние, постоянная ось пропускается. В турнире предпочтительнее меньший
ранг, а при равенстве — большее расстояние.

Равномерный кроссовер выбирает каждый ген у одного из двух родителей.
Мутация заменяет выбранный ген другой альтернативой той же категории.
Оба оператора сохраняют допустимость. Начальные комплекты формируются
независимым равновероятным выбором альтернатив.

Следующее поколение отбирается из родителей и потомков: сначала включаются
целые фронты, последний фронт при необходимости сокращается по расстоянию
до скопления. Недоминируемая сортировка и поддержание разнообразия — новые
механизмы по сравнению с ЛР1–ЛР2.

Внешний архив сохраняет недоминируемые решения среди всех оценённых кандидатов.
Он служит для анализа и не влияет на выбор родителей. Одинаковые векторы
критериев объединяются. Итоговый архив является приближённым фронтом:
неизвестное алгоритму решение ещё может доминировать одну из его точек.

Проведено по 20 запусков каждого метода. Остановка — исчерпание бюджета.
Оценки начальной популяции и повторившихся хромосом входят в бюджет.
Сохранённые родители повторно не оцениваются. Последнее поколение может быть
неполным. Параметры сохранены в [config.json](config.json).

Для взвешенной суммы критерии нормированы к [0, 1]:

f̃₁ = (Umax − U)/(Umax − Umin),

f̃₂ = (M − Mmin)/(Mmax − Mmin),

f̃₃ = (Rmax − R)/(Rmax − Rmin).

Границы получены отдельно по каждому критерию: суммами минимумов и максимумов
по категориям для полезности и массы, произведениями — для надёжности.
Совместный идеальный комплект с этими значениями может не существовать.
Минимизируется s(x) = w₁f̃₁ + w₂f̃₂ + w₃f̃₃.

| Профиль | Вес полезности | Вес массы | Вес надёжности |
| --- | ---: | ---: | ---: |
| 1 | 1.000 | 0.000 | 0.000 |
| 2 | 0.000 | 1.000 | 0.000 |
| 3 | 0.000 | 0.000 | 1.000 |
| 4 | 0.600 | 0.200 | 0.200 |
| 5 | 0.200 | 0.600 | 0.200 |
| 6 | 0.200 | 0.200 | 0.600 |
| 7 | 0.333 | 0.333 | 0.333 |

Последний профиль использует точные веса 1/3; в таблице они округлены.
Общий бюджет распределён между профилями: 600, 600, 600, 600, 600, 600, 600 оценок.
Для NSGA-II выполняется один совместный поиск с тем же общим бюджетом.
Операторы и вероятности совпадают. Для обоих методов в архив попадают
все оценённые кандидаты, включая промежуточные решения.
Для NSGA-II генератор инициализируется seed, для профиля j взвешенной суммы —
seed · 1000 + j, j начинается с нуля.

## Проверка качества

Полным перебором 59049 комплектов построен точный фронт
из 640 различных векторов критериев. Он используется для проверки,
а в поисковые алгоритмы не передаётся. Оценки перебора не входят в их бюджет.

Качество измеряется гиперобъёмом HV — объёмом объединения параллелепипедов
от нормированных точек до общей опорной точки [1.1, 1.1, 1.1].
При одной нормировке и опорной точке больший HV означает лучший охват области
критериев. Гиперобъём точного фронта HV* = 0.803257738.
Основной показатель — 100 · HV/HV*. Это доля гиперобъёма, а не процент
найденных точек точного фронта. Доля точных точек подсчитывается отдельно.

## Анализ и вывод

В проведённой серии NSGA-II лучше приблизил точный фронт по гиперобъёму. Средние значения составили 99.281% и 98.024%
соответственно; разница — 1.257 процентного пункта.
Средняя доля найденных точек точного фронта — 47.50%
для NSGA-II и 30.17% для взвешенной суммы.
Таким образом, близость HV к точному значению не означает восстановления всего фронта.

NSGA-II расходует поиск на несколько направлений одновременно и поддерживает
разнообразие. Взвешенная сумма зависит от выбранных предпочтений; даже при
точном решении скалярных задач она может пропускать точки невыпуклого фронта.
При одинаковом бюджете NSGA-II требует дополнительных сравнений для сортировки
по доминированию. Равное число оценок не означает равного времени работы.

Реализованы NSGA-II, недоминируемая сортировка, расстояние до скопления
и внешний архив. Получен набор содержательных компромиссов вместо одного ответа.
При использованном бюджете NSGA-II достиг в среднем 99.281%
точного гиперобъёма. Потеря менее 1% точного гиперобъёма показывает, что найденный набор хорошо приближает область компромиссов, хотя весь точный фронт не восстановлен.
Вывод относится к одному синтетическому набору и выбранным весам.
